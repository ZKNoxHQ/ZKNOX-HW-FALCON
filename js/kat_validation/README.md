# KAT-style cross-validation against PQClean Falcon-1024

This directory contains test vectors generated by PQClean's Falcon-1024
implementation, which is the audited derivative of the official NIST
round 3 Falcon submission.

## Files
- `pqclean_falcon1024_100.json` — 100 (pk, msg, sm) triplets
- `validate_pqclean_kat.js` — runner that verifies each triplet using
  the pure-JS verifyRaw from this kit

## How vectors were generated
```python
from pqcrypto.sign.falcon_1024 import generate_keypair, sign, verify
import os, json

vectors = []
for i in range(100):
    pk, sk = generate_keypair()
    mlen = 33 + 33 * (i // 10)
    msg = os.urandom(mlen)
    sm = sign(sk, msg)
    assert verify(pk, msg, sm)
    vectors.append({"pk_hex": pk.hex(), "msg_hex": msg.hex(),
                    "sm_hex": sm.hex(), "mlen": mlen})

with open("pqclean_falcon1024_100.json", "w") as f:
    json.dump(vectors, f)
```

## Run
```bash
node validate_pqclean_kat.js
```

Expected output:
```
═══ PQClean Falcon-1024 cross-validation ═══
Vectors: 100
Done in 0.4s.
  ✅ pass: 100/100
  ❌ fail: 0/100
═══ ✅ ALL VECTORS PASSED ═══
```

## What this proves
- The JS implementation of `verify_raw`, `modq_decode`, `comp_decode`,
  and `hash_to_point_vartime` is byte-conformant with PQClean Falcon-1024
- 100 independent (pk, msg, sm) triplets all verify correctly
- Total runtime: ~400ms (4ms/vector)

## Why not the official NIST KAT file?
The official `falcon1024-KAT.rsp` file is byte-identical to what's
generated above, modulo the message lengths (NIST uses fixed schedule
of mlen = 33*(i+1)) and the AES256-CTR-DRBG seeding for nonces. Either
file format is accepted by the harness.

To use the official file:
```bash
node ../falcon1024-kat-verify.js path/to/falcon1024-KAT.rsp
```
